# 📜 Nix Authority & MCP-NixOS Mandatory Lookup Sequence

All agents authoring, refactoring, or auditing Nix code (NixOS modules, Home Manager modules, flake outputs, or package derivations) MUST consult `mcp-nixos` as the single source of truth.

## Mandatory Lookup Sequence

When adding or modifying any Nix option or package dependency:

1. **Search Phase (`action: "search"`)**:
   - Query options or package names to confirm accurate attribute paths:
     - NixOS options: `nix {"action":"search","query":"<option>","type":"options"}`
     - Home Manager options: `nix {"action":"search","source":"home-manager","query":"<option>"}`
     - Packages: `nix {"action":"search","query":"<pkg_name>","type":"packages"}`

2. **Info Verification (`action: "info"`)**:
   - Verify package availability, version, broken status, and exact outputs:
     - `nix {"action":"info","query":"<pkg_name>"}`

3. **Browse Structure (`action: "browse"`)**:
   - Inspect underlying option definitions and submodule hierarchy:
     - `nix {"action":"browse","query":"<option_or_attr>"}`

4. **Version & Channel Check (`nix_versions`)**:
   - Confirm version evolution and deprecation timelines across unstable/stable channels.

5. **Pinned Source Verification**:
   - Verify that all nixpkgs derivations resolve to store paths generated by pinned flake inputs, avoiding unpinned `npx` or legacy channels.

## Execution Rules
- Never guess option names, package names, or deprecation status.
- Ensure all harnesses (Antigravity, Gemini, OpenCode, Hermes, Kiro, Pi) have `mcp-nixos` connected over stdio using executable `${lib.getExe pkgs.mcp-nixos}`.
